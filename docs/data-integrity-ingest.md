# 不正データの入口を塞ぐ（作成時バリデーション × 直接DB入力 × 防御読取り）（EXP-65）

- 実験: `internal/ingestlab` / `MYSQL_DSN=... go test ./internal/ingestlab/ -run TestEXP65 -v`
- スキーマ: `internal/ingestlab/schema.sql`
- 根拠: EXP-45（[dead-letter](dead-letter.md)・すり抜けた poison の隔離）/ `調査` §2.7（冪等）

## 何が起きるか

通常の動作確認では入らないデータが混入して、worker の処理が前に進まなくなる（1件の poison が
キュー先頭で詰まる・例外で落ちる・無限リトライする）。混入の**入口は2つ**ある。

1. **作成時バリデーションの不備** — アプリの作成経路でチェックが漏れている（状態の未知値・負の数量・
   存在しない参照・必須欠落）。
2. **直接 DB 入力** — 手動 SQL・別ツール・移行スクリプト・管理画面が**アプリを迂回して**書く。
   アプリのバリデーションはこの経路を**一切通らない**。

## こうあるべき

### ① 入口は多層。ただし最後の砦は必ず DB 制約

| 層 | 守る経路 | 例 |
| --- | --- | --- |
| アプリの作成時バリデーション | **アプリ経路のみ** | 状態・数量・参照の妥当性チェック（早く・親切なエラーで弾く） |
| **DB 制約（最後の砦）** | **全経路（直接 DB 入力も含む）** | `NOT NULL` / `ENUM` / `CHECK` / `FOREIGN KEY` / `UNIQUE` |

**アプリのバリデーションだけでは足りない。** 直接 DB 入力はそれを迂回するので、
「不正な行は物理的に書けない」状態を **DB 制約**で作る。EXP-65 は同じ不正 INSERT が、
制約なし表には landing し、`ENUM`+`CHECK`+`FK` の表には**入口で弾かれる**ことを測る。

- `ENUM('pending','in_progress','completed')` … 未知の状態を弾く
- `CHECK (amount >= 0)` … 負値を弾く（MySQL **8.0.16+** が enforce）
- `FOREIGN KEY` … 存在しない参照を弾く（マルチテナントでは**参照先もテナント込み**で設計）
- `NOT NULL` / `UNIQUE` … 欠落と重複を弾く

> **STRICT sql_mode が前提。** これが無いと ENUM は `''` に、範囲外は丸められて**弾かれずに landing** する。
> MySQL 8 の既定で入るが、明示的に確認する（EXP-65 は `@@sql_mode` を記録して検証する）。

### ② それでも DB で表せない前提違反は残る → worker は読取り時も防御する

DB 制約は「型として不正」を防ぐが、「値は正しいが業務前提を満たさない」（例: 参照先が論理削除された・
数量が0で処理対象にならない・状態の組合せが不整合）は防げない。だから **worker は DB の行を
"信頼できない入力" として読取り時に検証**し、処理できない行は**先頭で止めず隔離**する。

- 処理不能と判定したら **EXP-45 の DLQ（dead）へ隔離**し、良い命令は流し続ける（キューを止めない）。
- 隔離は消さずに残し、**アラート**して人が原因（＝どの入口から入ったか）を調べ、修正後に replay。
- worker は「想定外の値で panic して落ちる」のではなく、「1件を隔離して次へ進む」を既定にする。

## 仮説（未検証）

> EXP-65 は「制約が不正 INSERT を弾く／正しい行は通す」までを測る。以下は設計仮説で未計測。

- **H1: 制約は正常系のスループットをほぼ落とさない。** `CHECK`/`ENUM` は行単位の軽い評価、`FK` は
  参照先の主キー索引を1回引くだけ。書き込みホットパスが FK 先の競合で詰まる場合のみ要注意。
- **H2: 直接 DB 入力を完全に消すより、DB 制約で「書けなくする」方が安い。** 運用ルール（手で SQL を
  打たない）は破られる。制約は破られない。
- **H3: 入口の不正は「作成時に弾く」方が「worker で拾う」より桁で安い。** 混入後は調査・隔離・replay・
  再発防止のコストがかかる。入口（アプリ検証＋DB 制約）に寄せるほど総コストが下がる。

## 一行でまとめると

**アプリのバリデーションはアプリ経路しか守らない。直接 DB 入力を止める最後の砦は DB 制約（ENUM/CHECK/FK/NOT NULL、STRICT 前提）。それでも残る業務前提違反は worker が読取り時に検証し、EXP-45 で隔離してキューを止めない。**
