# EXP-6 マイグレーション途中の crash — 半端な状態を成功扱いしない

再現:

```bash
eval "$(./scripts/mysql-up.sh --export)"
go test ./internal/repo/ -run TestEXP6 -v -timeout 20m
```

結果ファイル: [`docs/results/exp-6/20260903-121040-migration-crash-matrix.md`](results/exp-6/20260903-121040-migration-crash-matrix.md)
（実験は本番用とは別のデータベース `workerdb2` に対して行う）

---

## 1. 2つの性質を分けて測る

| 性質 | 対策 | 確かめ方 |
| --- | --- | --- |
| **同時に走らせない** | `GET_LOCK`（接続固定） | 8プロセス同時起動 |
| **途中で落ちる** | `started` → `done` の二相記録 | 各段階で SIGKILL |

**ロックは crash には効かない。** 逆に二相記録は同時実行を防がない。両方要る。

## 2. 各段階で落としたあと、次の起動は何をするか

| 落ちた段階 | 落ちた直後の状態 | 次の起動 |
| --- | --- | --- |
| ロック取得前 | 記録なし | 完了 |
| ロック取得後 | 記録なし | 完了 |
| `started` 記録後 | `1:started`（成果物 0/4） | **停止**「途中で終わっている」 |
| DDL 途中（2文の間） | `1:done,2:done,3:started`（成果物 3/4） | **停止**「途中で終わっている」 |
| DDL 後・`done` 記録前 | `1:started`（成果物 1/4） | **停止**「途中で終わっている」 |
| `done` 記録後 | `1:done`（成果物 1/4） | 完了（残りを当てる） |
| 全部終わったあと | `1:done,2:done,3:done`（成果物 4/4） | 完了（何もしない） |

**成果物が無いのに `done` と記録されたものは 0 件。**
「当たっていないのに適用済み」は、いちばん見つけにくい壊れ方なので、
これがゼロであることを毎回検査している。

### DDL 途中の状態は実在する

`0003` は「列を足す」「その列に索引を張る」の2文からなる。
その間で落ちると **列はあるが索引が無い**（成果物 3/4）状態が残る。
MySQL の DDL は暗黙コミットなので、**これを巻き戻す方法は無い。**
だから「気づく」ことだけが対策になる。

## 3. 同時起動

| 条件 | 結果 |
| --- | --- |
| 8プロセス同時（crash なし） | 成功 8 / 失敗 0 / 記録されたマイグレーション 3 件（重複なし） |
| 8プロセス同時 ＋ 1つが DDL 適用後に crash | **成功 0 / 失敗 8** / 途中のまま残った記録 1 件 |

落ちたプロセスの `GET_LOCK` は接続が切れて即座に解放されるので、
次のプロセスがロックを取れる。そして **「途中で終わっている」を見つけて止まる。**
勝手に同じ DDL を流し直さない。

### ★運用上の代償（重要）

crash 後は **全プロセスが起動できなくなる**（上の表の「成功 0」）。
安全側だが、可用性としては**全台停止**を意味する。

- **マイグレーションはアプリの起動時ではなく、別のジョブで流す**
  （そうすればアプリ本体は止まらない。`docs/locking.md` 1 の結論と同じ）
- 止まったときの手順を先に決めておく:
  1. `schema_migrations` の `started` 行と、実際の成果物を突き合わせる
  2. DDL が当たっていれば `done` にする / 当たっていなければ行を消す
  3. どちらか分からない場合はバックアップから復元する（EXP-11）

## 4. 適用済みファイルの改変

適用済みの `.sql` を書き換えると、checksum が合わず起動を止める。

```
適用済みのマイグレーションが書き換えられている: 0001_robot_profile
（適用済みのファイルは書き換えず、新しい番号を足すこと）
```

「開発環境では動くが本番だけ形が違う」という壊れ方を、起動時に止める。

## 5. 実験の作り方（再利用できる点）

本番のマイグレーション処理（`repo.Migrate`）を**そのまま呼んでいる**。
実験用の別実装は作らない。段階の注入は `Options.MigrationHook` で行い、
本番は何も渡さないので挙動は変わらない。

```go
db, _ := repo.Open(dsn, repo.Options{
    MigrationHook: func(stage string) { ks.Point(stage) },  // 実験のときだけ
})
```

## 6. 適用範囲と未検証

- MySQL 8.0 / マイグレーション3本（うち1本は2文）/ 実験用データベース
- **MySQL の DDL は暗黙コミットするので、複数文のマイグレーションを巻き戻す方法は無い**
- バックアップからの復元は未検証（EXP-11 で扱う）
- オンライン DDL（`ALGORITHM=INPLACE`）の途中で落ちた場合の残骸は未検証
- レプリカへの伝播中に落ちた場合は未検証
